# Roadmap

Stu is in active development and not yet at v1.0 (v1.0 is the first production go-live).

## Next

1. **Email from Stu, short term:** one sending flow (the organization's shared mailbox, set in its settings; blank keeps copy and paste), wired into the Invite page (request 42) and the Occupancy verification page (request 43). These lead to communicating with homeowners through Stu, with replies captured on the occupancy (request 41).
2. **After the invitations:** reminders and the next-household step when a reply-by date passes; locking a round's records to a Lottery Administrator role (with the security work). The results PDF already says how to repeat a draw by hand; a ready-made spreadsheet for it is optional.
3. **Project homes as a picker** (request 12).
4. **Map the remaining workflows** (resale, annual verification, requests, insurance, leaving without a sale): trigger, steps, records changed, documents and flows.
5. **Rollup columns by script** (docs/STEP4-columns.md): test whether the Web API can create them, so that hand step goes away.
6. **More environment variables:** forms settings, verification link template, ACH draw day, approver email.
7. **Stewardship flows:** annual verification, insurance renewals, homeowner requests, and keeping Current occupancy up to date.
8. **Security:** roles (Staff, Intake Reviewer, Certifier, Board / Read-only), column security on income, asset values, dates of birth and demographics. With one app, roles are what separates intake data from stewardship staff.
9. **Offer homes** to certified households in list order (request 25), then **the handoff to stewardship** at purchase and sale agreement. Also: the document checklist at certification, document transfer for certified households, certifications expiring on their date, funder reporting.

## Later

- Starter forms for each supported forms platform, with their mapping files, so a new CLT can copy a form instead of building one.
- Fetch income limits from HUD USER's Income Limits API instead of typing them in each year.
- Deploy by GitHub Actions, and a managed solution package for CLTs that prefer to import one.
- Business process flows for Application and Sale; a dashboard home page.
